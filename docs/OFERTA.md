# Договір оферти

Сторінка: **/offer/** (посилання «Договір оферти» в підвалі лендинга).
PDF: **/oferta.pdf** (кнопки «Завантажити PDF» на сторінці договору).

## Звідки береться текст

```
content/oferta.docx  ──scripts/oferta-html.py──▶  content/oferta.html  ──▶  сторінка /offer/
                                                                       └──scripts/oferta-pdf.mjs──▶  public/oferta.pdf
```

- `content/oferta.docx` — оригінал договору, як його надіслано.
- `scripts/oferta-html.py` переносить текст **дослівно** (через pandoc)
  і лише розставляє розмітку: заголовки розділів, картку «Коротко про
  головне», таблицю повернень, реквізити, додатки. Юридичний текст руками
  не передруковується.
- Сторінка `app/offer/page.tsx` читає `content/oferta.html` на збірці й
  будує зміст із тих самих заголовків.
- PDF друкується з тієї самої сторінки, тож текст у PDF і на сайті
  однаковий. Стиль той самий, лише тло біле — під друк.

`content/oferta.html` і `public/oferta.pdf` — згенеровані файли, руками
їх не правлять.

## Нова редакція договору

1. Замінити `content/oferta.docx` новим файлом.
2. `npm run oferta` — оновить `content/oferta.html`. Якщо будова документа
   змінилась (інша назва, немає розділу 18 тощо), скрипт зупиниться й
   скаже, що саме не так.
3. `npm run build`, потім `npm run oferta:pdf` — новий PDF.
   Потрібні pandoc і Chromium; шлях до Chromium, якщо Playwright його не
   бачить: `CHROME=/шлях/до/chrome npm run oferta:pdf`.
4. Закомітити всі три файли: `.docx`, `.html`, `.pdf`.

Пункт 2.4 договору: нову редакцію треба розмістити **щонайменше за 7 днів**
до набрання чинності, з датою розміщення. Дата редакції — у першому рядку
самого `.docx`, на сайт вона потрапляє звідти.

## Відома пастка

pandoc позначає рядок заголовків таблиці класом `header` — а на сайті
`.header` — це фіксована шапка лендинга. Рядок «Ситуація / Що відбувається
з оплатою» прилипав до верху екрана, а в PDF висів на кожній сторінці.
Скрипт ці класи прибирає; якщо колись генеруватимете HTML інакше —
пам'ятайте про це.
